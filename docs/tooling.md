# Tooling guide

The tools follow the same pipeline: freeze inputs, generate or label positions,
train, select on development evidence, qualify on protected evidence, then
publish a bounded claim. A stage's receipt is the input to the next stage.

## Build, application, and publication tools

| Family | Responsibility | Starting point |
| --- | --- | --- |
| Build and test | Configure native targets, build, run CTest | `scripts/build-and-test.sh` |
| Documentation | Check local links, anchors, and historical exceptions | `tools/check_documentation_links.py` |
| Native engine tools | Play, export replays, run deterministic arenas | [Demo and replays](demo-and-replays.md) |
| Contest generators | Pack reviewed bot sources and verify generated bytes | [Submission tools](../submissions/codingame/tools/README.md) |
| Benchmark publication | Validate curated inputs and reproduce static summaries | [Reproducibility](reproducibility.md) |

## Replay-model research

| Entry point or module family | Responsibility |
| --- | --- |
| `jacek_replay_features`, `jacek_replay_corpus`, `jacek_rebuild_corpus` | Feature identities, sparse datasets, isolation, and frozen input composition. |
| `jacek_replay_train`, `jacek_replay_recovery` | Numerical training and exact historical replay validation. Recovery resume can repeat a complete training schedule. |
| `jacek_selfsearch_workflow` | Data generation, teacher labels, paired students, and campaign stages. |
| `jacek_replay_rebuild` | Candidate ladder, deadline, deterministic screening, and qualification. |
| `jacek_replay_rebuild_completion` | Standard-library-only reading of terminal summaries and their artifact bindings; no numerical or game replay. |
| `jacek_selfsearch_exploratory` | The separately governed exploratory pilot. |

Read the [campaign catalog](campaigns.md) before invoking a historical runner.
Modules with `load`, `validate`, or `resume` in their names can perform expensive
recomputation. The completion reader checks saved evidence and returns the
historical outcome.

## Compact-model research

`compact_value_bfm_train` owns numerical training, quantization, scalar/ranking
metrics, and model/receipt contracts. Its function bodies and historical
profiles have compatibility checks; it is not a general utility collection.

| Module family | Responsibility |
| --- | --- |
| `campaign_v2`, `labels_v2`, `stream_v2`, `exclusion_index_v2` | Freeze inputs, generate/label positions, stream datasets, enforce exclusions. |
| `seed_process_v2`, `prediction_pool`, `training_*_v2`, `parallel_store_v2` | Process ownership, worker capacity, numerical threads, memory, and validation execution. |
| `pilot_v2`, `pilot_selection_v2`, `full_v2`, `full_selection_v2` | Govern phase transitions and freeze eligible candidates. |
| `search_v2`, `category_profile_v2`, `intervention_v2`, `attribution_v2` | Profile or explain a candidate under the declared experimental scope. |
| `development_v2`, `opponent_suite_v2`, `protected_v2` | Evaluate strength without mixing development and protected evidence. |
| `release_v2`, `ci_v2`, `live_v2`, `terminal_outcome_v2` | Bind a source release, exact CI, live evidence, and terminal interpretation. |
| `rank4_teacher_*` | Earlier challenger, training, release, and dual-final contracts. Historical branch names belong to those frozen protocols. |

All names in the compact table have the `compact_value_bfm_` prefix. Use a
module's `--help` and its linked protocol guide for exact arguments. Raw run
directories are not script libraries and must not be imported as current
implementation code.

## Reading unfamiliar code

Start at the CLI entry point, identify the stage's input and output receipts,
then follow validation before execution. Tests under `tests/codingame/` show
small valid fixtures and rejection cases. The [architecture guide](architecture.md)
covers native boundaries; [historical evidence](history.md) explains which
files must retain their original bytes.
