# `jacek_arena_bfm`

`jacek_arena_bfm` is the clean-room bot and data lineage for the fresh-arena
campaign.  Its engine, bootstrap weights, scratch games, and labels were
created in this namespace after the campaign boundary.  It does not load an
older submission, checkpoint, action, label, replay, or corpus.

## Engine contract

- The immutable board topology has 105 vertices and 316 playable undirected
  edges.  Goals, own goals, rebounds, boundary rebounds, blocking, and the
  contest direction protocol are handled directly by `engine.cpp`.
- Search actions are complete rebound turns.  Equal successor boundaries are
  deduplicated before search.
- `Fixed250NineOne`, `TacticalProgressive`, and `PriorityBeam` generators are
  measured against an 8,192-action high-cap recall generator.  The selected
  operational default is tactical progressive widening: at most 512 root and
  256 non-root actions.
- Features are mover-relative: 316 edge bits plus one of eight true-turn
  distance buckets for each of 105 vertices, for 1,156 inputs total.
- Generator ordering, sparse-feature accumulation, and action tie-breaking are
  canonical in mover-relative coordinates.  The exact tests require bit-equal
  color-swapped evaluation, identical rotated generator order, and identical
  fixed-node search boundaries.
- The scalar evaluator is bias-free `1156 -> H -> 32 -> 1`, with `tanh` after
  every layer. Fresh training emits RFC 4648 base64-packed symmetric-int8
  weights. The checked-in `model.hpp` is the selected seed-101 result trained
  from random initialization on the frozen cumulative 8,000-game scratch
  corpus; it contains no arena-derived row.
- Search is single-threaded UCT-style best-first minimax, with 80,000 nodes as
  a second hard bound. The uploaded collection source used 800/155 ms. The
  current offline source uses 780/128 ms plus deadline-aware complete-turn
  generation and a 6 ms finalization reserve; it has not been uploaded.

## Fresh scratch corpus

`selfplay_generator.cpp` accepts no checkpoint, replay, action, or label input.
It distributes games across procedural opening depths `0,4,8,12` and supports
non-overlapping deterministic shards through `--start-index`.  Game JSONL
retains complete turns for independent replay.  `--rows` instead writes the
validator-native dense 1,156-feature value rows, including a canonical SHA-256
for each generated game:

```sh
c++ -std=c++20 -O3 \
  submissions/codingame/bots/jacek_arena_bfm/selfplay_generator.cpp \
  -o /tmp/jacek_arena_bfm_selfplay
/tmp/jacek_arena_bfm_selfplay \
  --games 2000 --seed 0x4a4143454b465245 --rows \
  --campaign-id CAMPAIGN_ID --timestamp T0_OR_LATER_UTC \
  --producer-source-sha256 EXACT_SUBMISSION_SHA256 \
  --output CAMPAIGN_OWNED_OUTPUT.jsonl
```

Every row labels the pre-decision position from its mover's perspective.  The
raw trajectory outcome is a value target only; it is not presented as a proof
that every losing-game position was theoretically losing.

The frozen scratch evidence contains 8,000 entirely new games.  The
first 2,000-game random-bootstrap shard is bound by manifest

## Corpus payload availability

The nine dense row payloads for the frozen 8,000-game corpus total
853,559,862 bytes and are campaign-local, intentionally Git-ignored
artifacts. Their tracked content-addressed manifests record exact paths, byte
counts, SHA-256 identities, producer sources, and lineage; the selected model
and its manifest remain checked in. A clean checkout therefore contains the
audit manifests but not `results/jacek_arena_bfm/scratch/rows/`. The validation
and retraining commands below are reproducibility recipes for a workspace
where those nine payloads have first been restored at the manifest paths and
verified against the recorded hashes; they are not clean-checkout CI commands.

## Validate and retrain the frozen scratch bootstrap (restored payloads required)

Both validation and training require the exact frozen window plan and pre-T0
ID-only exclusion registry, plus every content-addressed producer source named
by the supplied rows.  Arena rows additionally require their immutable
90-game derivation through a repeated `--arena-derivation` argument; the
trainer refuses validation/final-holdout derivations and rows. A single focus
operational failure (one attributable to our submitted bot) makes the entire
90-game derivation unusable for training; clean-looking games from that window
cannot be selected around the failure.

The current 2,000-game bootstrap can be checked without creating an artifact:

```sh
.venv/jacek_arena/bin/python \
  submissions/codingame/bots/jacek_arena_bfm/fresh_corpus.py \
  --corpus results/jacek_arena_bfm/scratch/rows/bootstrap-v2-2000.rows.jsonl \
  --window-plan results/jacek_arena_bfm/window_plans/0ca942c0a05af9e80197b5c95ea3ef32aed78192753f313a1015a22bd3b90d29.json \
  --exclusions results/jacek_arena_bfm/exclusions/0ce7cff1d29cbceab1d06a9066eebb6647a31515437cd468ff1a9b1b5f8407f9.json \
  --producer-source results/jacek_arena_bfm/scratch/producers/a33ab943e340bbc7537f48ef8dc467b51cb102426b42dcc688dee41dba70d465.source \
  --repository . \
  --campaign-root results/jacek_arena_bfm
```

This exact scratch-only retrain writes to a new temporary directory, never the
active `model.hpp` or submission:

```sh
campaign_model_dir="$(mktemp -d /tmp/jacek_arena_fresh.XXXXXX)"
.venv/jacek_arena/bin/python \
  submissions/codingame/bots/jacek_arena_bfm/train_fresh.py \
  --corpus results/jacek_arena_bfm/scratch/rows/bootstrap-v2-2000.rows.jsonl \
  --window-plan results/jacek_arena_bfm/window_plans/0ca942c0a05af9e80197b5c95ea3ef32aed78192753f313a1015a22bd3b90d29.json \
  --exclusions results/jacek_arena_bfm/exclusions/0ce7cff1d29cbceab1d06a9066eebb6647a31515437cd468ff1a9b1b5f8407f9.json \
  --producer-source results/jacek_arena_bfm/scratch/producers/a33ab943e340bbc7537f48ef8dc467b51cb102426b42dcc688dee41dba70d465.source \
  --repository . \
  --campaign-root results/jacek_arena_bfm \
  --hidden1 32 --seed 101 --epochs 4 --batch-size 512 \
  --learning-rate 0.001 --arena-exposure 0 \
  --output-header "$campaign_model_dir/model.hpp" \
  --output-model "$campaign_model_dir/model.npz" \
  --output-manifest "$campaign_model_dir/manifest.json"
```

Outputs are immutable: an existing path is accepted only if its bytes are
identical.  The model manifest records exact corpus, plan, exclusion,
producer, arena-derivation, trainer, float-weight, quantized-weight, and NPZ
hashes, along with whole-parent-game split and realized arena exposure.
